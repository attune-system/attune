# Least-privilege PostgreSQL access for action and sensor managers

Scope is Attune PR #102 at `fd78752e607754f7d42740229a6cade047bd245d` and stock PostgreSQL 16 and 18. A confined direct connection is feasible for selected operations if PostgreSQL authenticates each process and the server owns the work transitions. The existing API-only path already keeps platform credentials on the control plane. The current direct binaries would need repository and deployment changes to offer a comparable boundary. [Manager deployment](../deployment/api-only-managers.md#L289-L318)

## Authority to preserve

An action’s managing pack, the execution’s attributable owner and its assigned process are separate identities. Keep the explicit `execution_authority_selection`, active delegated owner and permission ceiling, immutable executable and schema, opt-in child token, and attempt-fenced Key-read provenance. Recorded control requires its admitted policy, dependency and approval checks and coordinated consumer readiness. Missing or revoked recorded evidence denies the operation. Input origins govern disclosure. The admitted output schema and channel policy determine which results are protected. ## Disposable PostgreSQL probe

On PostgreSQL 18.6, two authenticated action logins inherited the same capability role and had no base-table access. A single guarded settlement function resolved the registration from `session_user`, locked it and the assignment, and checked the expected attempt, release, running state and database-time deadline. Eleven assertions passed. Each login could settle its own assignment. The function rejected a same-role peer assignment, wrong attempts and releases, revoked and expired registrations, and a second transition on a terminal assignment. The sensor role lacked execute permission, and the action login lacked table access and permission to assume the function owner role. Final row checks confirmed that exactly the two owned live assignments changed.

The probe used a temporary schema in a disposable container with no published ports. It established the role and function pattern on one seeded operation. It did not use Attune's schema or test idempotency receipts, concurrent replacement, sensor lifecycle, or a production deployment. PostgreSQL 16 compatibility still needs an execution check.

## Feasibility and acceptance

- Provision a distinct, nonprivileged login per process incarnation or bind an independently issued incarnation credential to the login in private state. A shared pool login, `application_name`, custom settings and caller-supplied IDs cannot prove the process identity. Keep ownership, escalation memberships and DDL away from manager logins. Use verified TLS and authenticated database ingress. Definer operations need a dedicated owner with only required rights, a fixed trusted `search_path` with `pg_temp` last, and a selective `EXECUTE` grant with `PUBLIC` removed in the creation transaction. [PostgreSQL 16 session authorization](https://www.postgresql.org/docs/16/sql-set-session-authorization.html) · [PostgreSQL 18 session identity](https://www.postgresql.org/docs/18/functions-info.html#FUNCTIONS-INFO-SESSION) · [role membership](https://www.postgresql.org/docs/18/role-membership.html) · [custom settings](https://www.postgresql.org/docs/18/runtime-config-custom.html) · [connection authentication](https://www.postgresql.org/docs/18/auth-pg-hba-conf.html) · [TLS verification](https://www.postgresql.org/docs/18/libpq-ssl.html) · [definer security](https://www.postgresql.org/docs/18/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY)
- Keep the same lock order and database-time lease/deadline checks across validation and mutation. RLS predicates that read other tables can race with changes to authority. Verify that withdrawal or replacement fences existing pooled connections, that cancellation and completion have one durable winner, and that identical retries return the prior receipt while changed evidence fails. A definer function runs in the caller’s transaction, and a definer procedure cannot commit it. Test delayed commit as well as delayed statements. Where freshness or disclosure depends on a trusted commit or response boundary, let the trusted service own the transaction and release committed, still-authorized results. [PostgreSQL 18 row security](https://www.postgresql.org/docs/18/ddl-rowsecurity.html) · [transaction isolation](https://www.postgresql.org/docs/18/transaction-iso.html) · [explicit locking](https://www.postgresql.org/docs/18/explicit-locking.html) · [PostgreSQL 16 CREATE PROCEDURE](https://www.postgresql.org/docs/16/sql-createprocedure.html) · [launch freshness](../../crates/api/src/routes/manager_actions.rs#L216-L225)
- Include database-wide channels in the boundary review. PostgreSQL `NOTIFY` is visible to users of the same database independently of RLS. Current execution and event notifications carry IDs, refs and trace metadata. A direct profile that promises cross-pool metadata isolation must first make the notification path suitable for that trust level and treat wakeups as hints for authorized rereads. [PostgreSQL 18 NOTIFY](https://www.postgresql.org/docs/18/sql-notify.html) · [execution notifications](../../migrations/20260902000001_execution_notification_trace_tag.sql#L21-L49) · [event notifications](../../migrations/20260902000002_related_notification_trace_tags.sql#L11-L37)
- Account for authority outside SQL. The unchanged action path retains RabbitMQ, the platform JWT signer and the platform encryption key. The direct sensor uses RabbitMQ and the signer for worker transport, and uses the encryption key where configured for protected config and rules. Shared files and host access have separate controls. For a confined profile, keep platform keys and provider credentials in trusted services, constrain or mediate broker access, and isolate pack, runtime, artifact and custody storage. Verify that action and sensor child environments and mounts expose only their scoped credentials and required data. [Worker secrets and transport](../../crates/worker/src/service.rs#L558-L623) · [sensor encryption and transport](../../crates/sensor/src/service.rs#L245-L269) · [sensor config restoration](../../crates/sensor/src/sensor_manager.rs#L1216-L1231) · [sensor rule restoration](../../crates/sensor/src/sensor_manager.rs#L1552-L1563) · [child-process boundary](../deployment/child-process-environments.md#L138-L158)
- Acceptance needs disposable PostgreSQL 16 and 18 role tests and real manager-path tests. Prove allowed actions for the owning login and denial across role, pool, slot, boot, attempt, generation and release. Verify that no manager can access unrelated rows, raw secrets, IAM or approval state, arbitrary outbox or event writes, or an alternate path through `PUBLIC`, partitions or file access. Exercise replacement, revocation, lease expiry, concurrent capacity/placement, result replay, stale sensor writes, staged transfer races and custody handover. Confirm that missing recorded evidence fails closed and ordinary API, executor, supervisor and notifier behavior is preserved. [Existing manager test scopes](../deployment/api-only-managers.md#L269-L287) · [recorded consumer test inventory](../architecture/recorded-consumer-readiness.md#L8-L28)
- Evaluate the performance case with matched workloads and storage. Measure offer-to-start, terminal commit-to-executor notification, end-to-end workflow latency, and total SQL calls and lock time. The API publisher’s one-second tick is an independent source of workflow delay. A comparison should hold durable completion and broker semantics constant or report their contribution separately.
