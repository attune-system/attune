# Foreground G interoperability stage

G's prerequisite source commits are not copied into this worktree or claimed as
E work. After integrating G's real sources, each lifecycle profile supplies a
mode-0600 `interoperability_inputs_file` following
`scripts/acceptance/interoperability-inputs.example.json`. Pin every invoked
native binary, SDK entrypoint/jar/class, Playwright/Chromium and all twelve G probe
sources with actual hashes. Use the real centrally installed SDKs, never urllib/
fetch replacements or copied whole SDK trees. The archive helper is a separate
centrally compiled actual `interoperability_acceptance_archive` example; the native
artifact recipe builds/exports/checks it and G's separate real
`interoperability_inspector`. Integrate G's four follow-ups `59285937`, `5c0f40f5`,
`6b03fac8`, `fdaa02ff` and its repository module export correction as prerequisites.
Do not copy old G repository exports, workers, probes or SDK trees over primary.

The driver invokes G's protected five-principal provisioner using the existing
exact-project operator password input. E then composes a new run-specific pack
with G's three exact worker/batch/emitter sources, six actions, two queues, one
rule/trigger pair, four SDK sets and named receipt/context/payload types. The
workflow has separate action metadata and a single-task graph. The input action's
one authored Key default is retained in action/workflow-task/rule/queue discovery;
managed bindings leave SDK refs explicitly empty and do not pass `input` literals.
The sponsor's actual Key ref is used, never its plaintext. Runtime/runtime_alt and
initial external_runtime sets contain only pack-local action read. The emitter set
permits only Events/Create on the owned input_tick trigger. No set is assigned to
human principals by E. Both queues are enabled/accepting but start without work.
Batch mode uses the canonical tunable `batch_size: {source: literal, value: 2}`,
disabled coalescing and secret item fields. Omitted ack_contract keeps ordinary
completion ACK behavior; no fabricated ACK or output token is added. Public config
default remains integer 5. This fixture uses real registered core.python and actual worker
images from the already native-inclusive core deployment, not a fake native
runtime or copied SDK implementation.

E calls actual PackStorage through the compiled helper, measures its returned
canonical archive, merges the real principal/artifact binding and awaits G's
concrete probe for a bounded 2..4 hours. No action is force-uploaded and no tests
are suppressed by E's composition. G's probe performs ordinary limited-deployer
upload and all mandatory transports/browser. The owned web port is ephemeral
loopback; web uses its actual nginx proxy instead of unreachable container DNS
names in the browser. The stage must complete before stop/wait/volume teardown.
Missing artifacts/lanes, false `interoperability_criteria_passed`, or
`full_sow_acceptance` other than false fail. Real service semantics and native SDK
interfaces remain runtime assertions, not assumed passing from source tests.

Each profile also requires `repository_inspector` with the measured executable
path/hash and `observer_credential_file`. That private credential contains the
actual `run_id`, `project`, ordinary SELECT-only `user`/`password`, `database: attune`
and exact `schema`. It is separately provisioned centrally, never borrowed from
the app/database owner/superuser. E generates a new mode-0600 template using the
actual mapped loopback PG endpoint, pins that template and inspector in the binding,
and supplies the actual canonical release digest. G alone derives a fresh MAC-key
context after upload using actual pack/actor IDs. E never invents these IDs, copies
F's inspector context, adds a decryption key, or accepts unsigned PASS output.

G's updated provisioner verifies the exact maintenance output-witness grants,
including own-pack execution read/decrypt, own-queue item read/decrypt and only the
actual sponsor Key read/decrypt. No installer/runtimeconsumer/reader privileges are
broadened by this fixture. Worker success is `completed`; JSON is under `result.data`
and may be protected as a whole. G's witness compares plaintext only in memory and
records receipt hashes, while the separate DB observer reads metadata only.

If G fails/times out, E stops container writers but retains owned volumes and
private recovery files until actual host-child/browser joining is established.
It does not assume that killing the parent of a separately sessioned browser
joined it. Successful cleanup unlinks only the five new G private credential files
and exact bindings/observer template after verified writer/resource teardown. G owns consent/
execution/native-profile/browser cleanup inside its foreground stage.

Offline metadata/wiring tests are not live receipt/SDK/browser acceptance. Central
must build the helper and supply all real artifacts, then run the existing owned
lifecycle command with both storage profiles. G enforces the complete mandatory
matrix counts and historical saved-pin assertions. Neither its unrun source nor
these offline fixture checks establish connected acceptance. Full SOW stays false.
