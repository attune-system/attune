# File custody for ordinary iteration outcomes

F consumes A's typed `NativeSnapshotStorageEvidence::iteration_outcome()` after
keyless authentication of the entire normalized member set and its original
release. This is a distinct INPUT observation, not an execution result, a wait,
cache EOF, ordinary failure metadata, or a future group recipe.

For every member F visits both `original()` and `latest()`. It retains each full
original `ActionSchemaBinding` through the existing contract-proof graph and
traverses that observation's exact input receipt/provenance edges. Each original
stored input field registers only its actual
`execution_config/<observed execution>/<original field path>` archived site before
pending raw-source resolution. It does not register execution-result sites or
substitute an aggregate field namespace for producer pointers.

Generic fields and contributor manifests are intentionally empty for this source.
The original encrypted input copies, schema, executable and independent manifests
remain inside A's one real NativeArchive. F counts each typed observation, field,
receipt and manifest under its global closure bound. A's byte reservation already
includes both original/latest copies, normalized members and release; F does not
double-charge ciphertext. It does not parse manifest attributes as grants or union
the original and selected retry ceilings. Input receipts and retained admissions
lead to their existing accepted-input and approval graphs.

The exact `ordinary_iteration_outcome/<snapshot>/""` source origin is terminal only
after that snapshot exposes the authenticated typed group. Discovery before its
receipt schedules the actual archive and leaves the origin pending. The final
retention guard rejects it unless that exact lifecycle identity was authenticated.
A different source kind at the same snapshot, nonempty path, nonpositive identity,
or unknown future kind cannot use this path. No self-recursing raw entity is added.

Existing physical-parent traversal retains each actual original/latest execution,
admission and frozen owner. No synthetic child snapshots, new parent enum, F node
kind, multi-predecessor walker, current child lookup or plaintext decryption is
needed. Existing staged receipt checks, graph gates, exact file reservations,
native predecessor deduplication and child-first pre-LIMIT cleanup remain intact.
Wait, ResultView and completion release getters are all None for this source.

## Prerequisites and validation scope

This focused adapter requires ALL A commits `d2b2a8fb`, `628303e9`, `b0d1cf3e`, their
01025 migration, and the matching D/J prospective input/iteration APIs. F read the
actual staged APIs without importing or replacing shared A/D/J implementations.
No migration bytes or setup/controller/journal behavior changed.

`crates/common/tests/support/file_native_iteration_outcome_cases.rs` authors two
real repository cases using D's prepare/apply to create and seal actual siblings,
and A's real group constructor for a failed earlier sibling plus a successful last
sibling. A literal carries the group's CONTROL dependency into the actual F file
keeper. Both raw member executions/config ciphertext and dispatch rows are removed
before the first file reservation. The test checks exact normalized member copies
and release identity, independent observation admission pins, protected normalized
rows, keyless readmission and exact object plus shared-staging release. Existing
bounded reclamation then removes the archive and cascades members/release.

The second case revokes one actual original member admission. Receipt replay must
deny despite the other member's retained ceiling, while keyless physical custody
remains positive. Neither case creates a superseding retry or measures real elapsed
approval expiry. Production traverses both original/latest observations, but those
runtime scenarios still need central execution with actual retry callers. There
is no claimed all-members grant union, synthetic retry or expiry acceptance.

The Rust unit source checks exact archive-origin discovery/authentication and
unknown-kind denial. Python guards inspect the typed adapter without running any
Rust/DB/kernel fixture. New repository tests remain uncompiled/unrun by the agent;
source checks do not establish provider, native settlement or disclosure readiness.
